# 領収書の出し忘れチェック（1画面デモ）

## 何ができるか
- カード・通帳の明細と手元の領収書の一覧を貼ると、「明細はあるのに領収書がない」「領収書はあるのに明細にない」ものを洗い出す。
- 「金額が同じで日付が近い（既定±3日）」ものを同じ取引と見なして1対1で照合する。
- 月ごとの件数・領収書なしの件数・合計と、結果のCSVが出る。

## 使い方
1. `index.html` をブラウザで開く（サンプルは架空のデータ。「サンプルを消す」で空になる）。
2. 左に明細、右に領収書を貼る。1行1件、「日付・メモ・金額」の順（Excelのコピー／カンマ区切りどちらも可）。
3. 「照合する」を押す。読めない行は赤く表示される。

## 対応する形式／対応しない形式（明細の貼り付け）
対応する（列は自動で推定。読み取った列は結果の上に表示）：
- タブ区切り（Excelコピー）・カンマ区切り（金額は引用符つき `"1,980"` かカンマなしが確実）。見出し行あり／なし。列が多くても、列の順番が違ってもよい。
- 推定の規則：日付＝日付形式に合う値が最も多い列／金額＝数字と `,` `¥` `円` だけの値が最も多い列（同率なら見出しに「金額」等がある列→値の種類が多い列→左の列。「残高・回数・番号」の見出しの列は除く）／メモ＝残りの文字列列のうち見出しに「店・先・摘要・内容」等があるか平均が最長の列。
- 日付：2026-10-03／2026/10/3／2026年10月3日／令和8年10月3日・R8.10.3／10/03（年は同じ明細の他の行の年を使う。無ければ今年）／時刻・曜日つき。全角数字・半角カナも可。
- 従来の「日付 メモ 金額」を空白で区切った1行1件も、今まで通り読める。

対応しない（限界）：
- 読めない行（日付・金額が空／0円／マイナス／小数／列が足りない／合計行など）は、照合に使わず「読み取れなかった行」に理由つきで出す（捨てない）。返金（マイナス）も読まない。
- 列の推定は行全体の傾向で決めるため、金額列が2つ以上ありうる明細（利用金額と支払金額が別、など）では見出しの語が頼り。違う列を拾った時は、日付・メモ・金額の3列に整えて貼り直す。
- 引用符の中に改行があるCSV、日付と金額が1つのセルに入っている形、`20261003` のような区切りなし日付、外貨明細は対応しない。
- 年なしの日付（10/03）は同じ年として読む。年末年始をまたぐ明細は、年つきの行を混ぜるか年つきで貼る。
- 引用符なしの `店,1,980` は列区切りか桁区切りか区別できない。全行の列数がそろう場合に限り桁区切りの金額として読み、画面に【注意】を出す（回数の列と金額が並ぶ `店,1,980` は誤読しうる）。`店,1,1980` のように桁区切りで説明できない形は読まず、エラーにする。
- 見出しなしで、全行が「結合が必要」な形（3行以上。`店,2,980` のような回数＋3桁以下の金額）は、桁区切りか回数か区別できないため金額を決めず「見出し行（日付,店名,金額）を付けてください」のエラーにする。1行でも結合不要の行（`1980` など）があるか、2行以下の場合は桁区切りとして読む（2行以下は誤読しうる）。
- 年のない日付（`12/30`）は、同じ列の年つき日付の年（最多）で補う。月が大きく巻き戻る（12月→1月など年をまたぐ）並びがあれば年を決められず、年なし行をエラーにする。年が全く無く巻き戻りも無い場合は今年として読み、画面に【注意】を出す（年が違う場合は年つきで貼り直す）。
- 見出し行なしで金額らしい列が2つ以上ある（残高・回数が隣にある等）時は、どれが金額か決められないため読まずに理由つきでエラーにする。見出し行に「金額」を入れるか3列に整える。日付の列が複数ある時も同様（年つきの列は年なしの列より優先）。
- 先頭行を見出しとして読み飛ばすのは、数字を含まず列数が他の行と同じ行だけ。外した行は画面（読み取った列の注記）に表示する。前置き行（`お客様名,サンプル様` 等）や日付が不正な1行目は外さず、エラー行に出す。日付のセルを持つ行が半数未満なら表と見なさず1行ずつ読む（`2026-09-05 車両 1,500,000` が読める）。
- 実データでの動作は未検証（検証は架空データのみ）。

## 限界
- 照合は目安。同額・近日付が複数あると、近い順に割り当てるだけで、取り違えはありうる。最終確認は目視。
- 税務判断（経費にできるか、科目）はしない。年なしの日付、小数・0円・マイナスの金額は読まない。
- 入力は画面内で処理し、保存も送信もしない（再読み込みで消える）。依存なしの単一HTML。

## 検証
- `node verify.mjs`：読み取り・照合の固定ケース＋乱数200回（真の対応との一致）＋カード明細CSVの固定ケース・列順/区切り/見出し/表記を変えた乱数300回。
- `node ui-check.cjs <playwrightのnode_modules>`：headless chromiumで画面操作・CSV・390px幅・外部通信0を確認。
